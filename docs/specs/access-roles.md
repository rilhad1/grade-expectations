# Доступ, ролі, ізоляція за коледжем

- Для кого: усі. Код `plugins/{session,permissions,tenant}.ts`, `packages/domain/src/permissions.ts`, `modules/auth`, `modules/me`, `modules/users`.

## Призначення

Хто що бачить і змінює: вхід, ролі, перемикач ролі, жорстка ізоляція даних між коледжами.

## Що робить зараз

- Better Auth (cookie-сесія), вхід за запрошенням, опційно Google; ліміт спроб IP + пошта.
- Ролі `TEACHER`, `MODERATOR`; один користувач може мати обидві (перемикач на клієнті).
- Права: `can(membership, action)`; сервер перевіряє `preHandler`-ами, веб лише ховає UI (не захист).
- Ізоляція: `forOrganization(prisma, orgId)`, дочірні моделі через зв'язки у `repo.ts` і `can()`.

## Правила й інваріанти

- Кожен новий запит/маршрут org-scoped, з тестом ізоляції (ADR-008).
- Викладач пише лише у власні навантаження; модератор керує структурою й розкладом, оцінки не редагує (OQ-3).
- Cookie першопартійні (проксі Worker), `X-Forwarded-For` з `cf-connecting-ip`.
- Безпека (CSP/заголовки, глобальний ліміт, CSV-ін'єкція, довжина `q`, зміна витеклих паролів) відкладена власником: не «виправляти» без прохання, не погіршувати.

## Напрямок

Фаза 3: `COMMISSION_HEAD`, `ADMIN`, `STUDENT`; Postgres RLS як другий рубіж; 2FA для модераторів (ROADMAP).

## Покращення (за пріоритетом)

1. Користувач із сесією, але без членства, не повинен потрапляти в цикл `/me` 401 ↔ `/login`.
2. Вхід очищує кеш React Query попереднього користувача.
3. Приймати запити лише від Worker (спільний секрет), щоб `X-Forwarded-For` не підроблявся при прямому зверненні до Render.
4. `session.ts`: `cookieCache` (3–5 запитів на кожен виклик).
5. `env.ts`: `WEB_ORIGIN` без слеша, `NODE_ENV` за замовчуванням.
6. Безпека за §5 беклогу: коли власник вирішить.

## Відкриті питання

- OQ-3, OQ-10; хто може бачити журнал, коли викладача замінили (OQ-22).
