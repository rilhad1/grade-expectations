# Атестації й відомості

- Для кого: викладач; перегляд дат для деканату. Маршрут `/attestations/$loadId`, код `features/attestations`, API `attestations`, `documents`.

## Призначення

Підсумувати семестр: пропозиція оцінки модуля («Модуль 1», рубіжна, директорська, залік/екзамен), підтвердження викладачем і формування відомості DOCX/PDF.

## Що робить зараз

- Пропозиція модуля (`moduleProposal`, `attestationFinal`) з кумулятивним розрахунком (OQ-23/24), «є» → «зар.», підтвердження.
- Відомість DOCX (шаблон `statement.docx`) і PDF (Gotenberg, опційно); лише повністю підтверджені результати (OQ-26).
- Банер найближчої атестації на «Сьогодні», смуга періоду над датами журналу.

## Правила й інваріанти

- Атестації й періоди по курсах (`course` 0/null = усі); вибір через `pickAttestation` із фолбеком на курс 0.
- «Модуль 1» = результат 1-ї рубіжної (INTERIM); колонки до «Модуль» і він сам INTERIM, після — DIRECTOR_TEST.
- Форма контролю: залік, крім графіки (екзамен). Навчальні дні рахуються по курсах (ADR-030).
- Підсумок оцінки не вигадується: лише підтверджене викладачем.

## Напрямок

Відомість одним кліком без ручного перенесення з таблиці; ROADMAP: зведені атестації для голови комісії (фаза 3).

## Покращення (за пріоритетом)

1. Дати `Attestation` застарівають після редагування `SemesterPeriod` (`ensureAttestations` копіює лише раз): продумати оновлення, не перезаписуючи ручних правок [питання].
2. `saveResults` у транзакції й з перевіркою `version`.
3. Макет відомості закладу (шапка, підписи, окремі форми екзамену/заліку; OQ-5/25).
4. Студенти не `ACTIVE` у відомості (OQ-27).
5. Смуга періоду перевірити на реальних даних.

## Відкриті питання

- OQ-1/2: як модулі складаються в підсумок; залік балом чи «зараховано».
- OQ-26: чи можна формувати відомість без повного підтвердження.
