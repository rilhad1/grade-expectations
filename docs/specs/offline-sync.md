# Офлайн і синхронізація, PWA

- Для кого: усі, але критично для викладача на парі. Код `apps/web/src/offline/*`, API `modules/sync`.

## Призначення

Пара не повинна залежати від Wi-Fi: відмітки й оцінки зберігаються на пристрої і доходять на сервер без втрат; установка як застосунок (ярлик).

## Що робить зараз

- Dexie `ge-offline`: заняття ±14 днів, outbox, кеш `me` і довідників; `applyOp` застосовує операції локально.
- `POST /sync/push` (ідемпотентно за `opId`), `GET /sync/pull?since=`; запуск кожні ~20 с і на `online`.
- **LWW по клітинці** за `editedAt` (майбутній час обрізається до серверного «зараз»); REST-запис теж ставить `editedAt`.
- PWA: оболонка в кеші Workbox, **`/api/*` не кешується** (ADR-020); холодний старт без мережі працює з кешу сесії.

## Правила й інваріанти

- Нічого не губити: операція лишається в outbox, поки сервер не підтвердив; 400/422 карантин, решта повторюється.
- Вихід з акаунта/зміна користувача очищує локальну БД (ADR-021).
- Нові поля в кешованих даних із м'якими значеннями за замовчуванням (`withDefaults`), інакше ламаються старі кеші.
- TanStack Query у `networkMode: 'always'`.
- Аудит у тій самій транзакції, що й зміна (ADR-016).

## Напрямок

Офлайн охоплює все, що потрібне на парі і в журналі; конфлікти показуються зрозуміло (OQ-31); польові випробування «тиждень без Wi-Fi» (ROADMAP «Перевірка 2»).

## Покращення (за пріоритетом)

1. Операція, що детерміновано дає 500, не повинна блокувати весь outbox.
2. Відповідь сервера в Dexie писати транзакційно й з перевіркою версії (стара не перезаписує нову).
3. `network.ts`: не вважати будь-який `TypeError` «офлайном».
4. Не опитувати у фонових вкладках (Neon не засинає).
5. `sync/pull`: оповіщати про передані заняття й зміни складу групи; зменшити запити (`getLessonDetail` на кожне заняття, ≈7 запитів на операцію push).
6. Ручне розв'язання конфліктів (OQ-31), офлайн-доступ до сітки журналу й розкладу (OQ-33).
7. Бекапи/моніторинг (Sentry, uptime) із ROADMAP фази 2.

## Відкриті питання

- OQ-29…33 (вікно копії, скасування завершення офлайн, очищення `SyncOp`, офлайн-сітка).
