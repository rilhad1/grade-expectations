# Спеки розділів

Кожен розділ застосунку має власний спек: **навіщо він є, що має робити, які правила не можна ламати, куди рухається і які покращення заплановані**. Спеки живі: їх читають перед роботою над розділом і оновлюють разом зі зміною поведінки.

## Як користуватися

1. Перед будь-якою зміною в розділі прочитай його спек (таблиця нижче) і суміжні, якщо чіпаєш спільні правила.
2. Зміна не повинна порушувати розділ «Правила й інваріанти». Якщо порушити треба, спершу виніс це на рішення користувача, потім онови спек і (якщо це архітектурне) додай ADR у `docs/DECISIONS.md`.
3. Після зміни онови: «Поточний стан» (якщо змінилась поведінка), «Покращення» (викресли зроблене або додай нове), «Відкриті питання».
4. Мітки в спеках: **[підтверджено]** слова користувача або ADR; **[пропозиція]** ідея, яку ще не схвалено (не робити без згоди); **[питання]** рішення, яке ухвалює користувач. Нічого не вигадувати щодо навчальних даних (планові години, теми, по батькові, статуси).
5. Безпека (§5 `docs/ui-redesign-backlog.md`) свідомо відкладена власником: у спеках позначена, але не робиться без прохання.

## Шаблон

```md
# Назва розділу

- Для кого / де в застосунку / код

## Призначення

## Що робить зараз

## Правила й інваріанти

## Напрямок

## Покращення (за пріоритетом)

## Відкриті питання

## Пов'язане (ADR, інші спеки)
```
