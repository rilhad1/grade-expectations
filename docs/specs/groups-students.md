# Групи і студенти

- Для кого: деканат. Маршрут `/admin/groups`, код `features/groups`, API `groups`, домен `studentList`.

## Призначення

Вести склад груп (когорти, групи по роках, підгрупи, студенти, зарахування зі статусами) і швидко завантажувати списки.

## Що робить зараз

- Створення груп, студентів, підгруп; імпорт списку ПІБ (`studentList`) з режимом dry-run.
- Зарахування зі статусами (активний, відрахований, академвідпустка…) і датами; м'яке видалення.

## Правила й інваріанти

- **Статуси студентів і по батькові лише з даних користувача** **[підтверджено]**.
- Видалення студента знімає й усі його зарахування (виправлено); група не показує видалених.
- Унікальність `Group(academicYear,name)` і `Subgroup(group,name)` не частково-унікальна: видалена група займає ім'я.
- Усе org-scoped (ADR-008).

## Напрямок

Склад групи завжди відповідає реальності на дату заняття; історія зарахувань зберігається.

## Покращення (за пріоритетом)

1. Частково-унікальні індекси `WHERE deletedAt IS NULL` для груп/підгруп/аудиторій.
2. `createSubgroup` дедуплікує `enrollmentIds`.
3. Підтвердження зміни статусу зарахування (відрахування/перевід).
4. Нормалізація апострофів (`'`, `’`, `ʼ`) при пошуку дублів.
5. Макети перегляду групи, студента (беклог).

## Відкриті питання

- OQ-27: як студенти не `ACTIVE` потрапляють у відомості й пропозиції.
- По батькові та статуси: чекаємо даних.
