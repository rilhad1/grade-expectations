# Мої дисципліни (програма, теми, правила)

- Для кого: викладач. Маршрут `/my-disciplines/$loadId`, код `features/disciplines`, API `programs`.

## Призначення

Тримати для кожної дисципліни тематичний план і правила оцінювання, від яких залежать розкладання тем по заняттях і розрахунок модулів.

## Що робить зараз

- Редактор тем за видом занять (`TopicPlanEditor`), редакції програми, автоматичне призначення тем заняттям (`assignTopicsForLoads`).
- Редактор правил (`RulesEditor`): ваги за видом, поріг пропусків, правило пропущеної контрольної.

## Правила й інваріанти

- Тематичні плани, планові години, по батькові тощо **не вигадуються**: лише з даних користувача **[підтверджено]**.
- Інформатика 1 і 2 курсів — різні дисципліни, окремі програми.
- Зміна шкали блокується, якщо вже є оцінки (сумарно по споріднених навантаженнях).
- `gradingRules` не має `.default()` в оновленні (ADR-010).

## Напрямок

Користувач передає тематичні плани обох інформатик; програми заповнюються з його даних і розкладаються по парах автоматично.

## Покращення (за пріоритетом)

1. Імпорт тематичних планів, коли користувач їх надасть (етап 6).
2. Колонка «Заняття» (дата, статус) у таблиці тем: потрібна прив'язка теми до заняття в API.
3. Правило `missedTest='ZERO'` або прибрати опцію з UI, поки воно не працює [питання].
4. Теми не переприсвоюються при скасуванні заняття без створення нового; `assignTopicsForLoads` поза транзакцією.

## Відкриті питання

- Планові години по дисципліні й групі та тематичні плани: чекаємо на дані користувача.
