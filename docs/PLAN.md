# План реалізації MVP — Grade Expectations

Джерело: `docs/concept.md` і промпт для Claude Code. Задачі розміром 0,5–1 день (0,5д = «п», 1д = «д»). Етапи 0–1 реалізуються в першій сесії, решта — після підтвердження плану.

## Стан середовища (перевірено перед стартом)

- Node 22.16 є. `pnpm` через corepack не запускається (спроба завантажити pnpm 12.9.1 закінчується помилкою): на етапі 0 потрібно зафіксувати `packageManager` у `package.json` і встановити pnpm явно.
- Docker не встановлено. Postgres для розробки й інтеграційних тестів без нього не підніметься (див. ризик R1).

## Етап 3. Деканат (≈20 д, найбільший)

Роки й семестри (3.1, д) → довідники: групи, потоки, студенти (3.2, д), імпорт з Excel з прев'ю (3.3, д), дисципліни, аудиторії, дзвінки (3.4, д) → навантаження (3.5, д) → конструктор розкладу: API версій і конфліктів (3.6, д), UI сітки з drag-n-drop (3.7, 3 д), діалог публікації з підрахунком «створено / змінено» (3.8, д) → `generate-lessons` і публікація (3.9, д) → запити на перенесення, API й екрани (3.10, 2 д) → майстер «Новий семестр» і `clone-from` (3.11, 2 д) → e2e Playwright для критичних сценаріїв (3.12, 2 д).

**Готово, якщо:** деканат створює семестр, розставляє навантаження, публікує розклад і всі викладачі отримують заняття; конфлікти видно наживо.

**Ризики:** R6 — UI конструктора (подвійні клітинки верх/низ + drag-n-drop) найскладніший; закладати запас; R7 — імпорт Excel (різні формати ПІБ).

## Етап 4. Викладач (≈16 д)

«Сьогодні» (4.1, д) → режим «На парі», mobile-first з optimistic updates (4.2, 3 д) → швидке оцінювання, шторка 1–12 (4.3, д) → журнал: TanStack Table + Virtual, клавіатурна навігація (4.4, 3 д) → картка студента (4.5, п) → розклад викладача, тиждень/день (4.6, 2 д) → тематичний план (4.7, д) → правила оцінювання (4.8, д) → вичитка годин (4.9, п) → контрольні й завдання (мінімум) (4.10, 2 д).

**Готово, якщо:** відмітити групу з 25 студентів можна за ≤15 с з телефона; оцінки з заняття видно в журналі.

## Етап 5. Атестації й документи (≈10 д)

Модулі за формою контролю (5.1, д) → розрахунок пропозицій і пояснення (5.2, д) → UI атестації з підтвердженням (5.3, 2 д) → pg-boss, експорт відомості DOCX через docxtemplater (5.4, 2 д) → PDF через Gotenberg (5.5, д) → ICS-підписка (5.6, д) → звіт про вичитку (5.7, д) → експорт усіх даних викладача у ZIP (5.8, д).

**Залежність:** шаблон відомості (OQ-5) — до 5.4 потрібен зразок документа закладу.

## Етап 6. Офлайн (≈10 д)

Dexie і снімок активного семестру (6.1, 2 д) → `outbox` і sync-воркер (6.2, 2 д) → `/sync/push`, `/sync/pull`, `ChangeLog` (6.3, 2 д) → вирішення конфліктів: LWW по клітинці, `version` для структури (6.4, 2 д) → PWA: кеш оболонки, індикатор синхронізації (6.5, д) → очищення локальної бази при виході, e2e з вимкненою мережею (6.6, д).

## Наскрізні вимоги

- Кожен етап закінчується зеленими `typecheck`, `lint`, тестами й атомарним комітом (Conventional Commits).
- Після зміни схеми — нова міграція, застосовані не редагуються.
- Невідоме правило → запис в `OPEN_QUESTIONS.md`, `TODO(OQ-n)` у коді, конфігурована заглушка.
