# Журнал рішень (ADR)

## ADR-001. Монорепо pnpm + Turborepo, TypeScript strict

- **Контекст.** Спільні типи й Zod-схеми між фронтом, бекендом і доменом.
- **Рішення.** pnpm workspaces, Turborepo, ESM усюди, строгі прапорці TS.
- **Наслідки.** Один `packageManager`; на машині розробника pnpm зараз не запускається через corepack — виправляється на етапі 0.

## ADR-002. `@ge/domain` — чисті функції без I/O

- **Контекст.** Ті самі правила потрібні на сервері й офлайн у браузері.
- **Рішення.** Пакет без залежностей від Prisma, fetch і Node API; 100% покриття гілок.
- **Наслідки.** Дати передаються рядками `YYYY-MM-DD`, а не `Date`, щоб уникнути проблем із часовими поясами.

## ADR-003. Ідентифікатори UUID v7 від клієнта і Better Auth

- **Контекст.** Офлайн-створення потребує id на клієнті; Better Auth за замовчуванням керує власною таблицею користувачів та генерує id.
- **Рішення (пропозиція).** Для доменних сутностей — UUID v7 з клієнта. Таблицю `User` узгодити з Better Auth через його `advanced.database.generateId`; перевірити на етапі 2 до написання коду.
- **Наслідки.** Якщо узгодження неможливе, лишаємо окремий `User` з посиланням на таблицю Better Auth.

## ADR-004. Поле `Lesson.manuallyEdited` (пропозиція, чекає підтвердження — OQ-7)

- **Контекст.** Регенерація не має чіпати вручну змінені заняття, але схема цього не відображає.
- **Рішення.** Додати булеве поле, що виставляється при ручній зміні дати, пари, аудиторії чи статусу.
- **Наслідки.** Невелика зміна схеми до першої міграції, тому нічого переписувати не доведеться.

## ADR-005. Інтеграційні тести проти справжнього Postgres

- **Контекст.** Docker на машині відсутній.
- **Рішення.** Тестова БД через Docker Compose (за промптом). Якщо Docker не буде встановлено, альтернатива — локальний Postgres 16 з тим самим `DATABASE_URL`.
- **Наслідки.** Домен-тести не залежать від БД і працюватимуть у будь-якому разі.

## Прийняті рішення (за делегуванням власника продукту)

Власник доручив приймати рішення самостійно; бізнес-логіку він скоригує окремо. Усе нижче вважається прийнятим і замінює «пропозиції» вище.

- ADR-003: UUID v7 від клієнта, `User` узгоджується з Better Auth на етапі 2.
- ADR-004: додати `Lesson.manuallyEdited` (OQ-7).
- OQ-8: окремий `TeachingLoad` на кожен вид занять, UI групує.
- OQ-9/OQ-2: `Grade.value` для PASS_FAIL — 1/0; заліки зберігаються у `AttestationResult.final` як рядок.
- OQ-10: 2FA відкладено до фази 2.
- OQ-11: лишаємо I семестр у seed; терміни переглядаємо після Перевірки 1.
- Docker: потрібен для етапу 0; якщо не встановлено, використовується локальний Postgres 16 (ADR-005).

## ADR-006. Версії залежностей (етап 0)

- TypeScript закріплено на 6.0.3: typescript-eslint 8.71 підтримує `<6.1`, а TypeScript 7 ще ні.
- MUI закріплено на 7.3.11 згідно з концептом (на сьогодні є v9); оновлення — окремим ADR.
- Версії у `package.json` — точні (без `^`), pnpm 12.9.1 через `packageManager`.
- Залежності зі скриптами збірки заборонені за замовчуванням (`allowBuilds`); дозволяти лише за потреби.
