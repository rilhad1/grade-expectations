# Що лишилося доробити після редизайну UI

Стан на момент злиття `feat/ui-redesign` у `main` (6 жовтня 2026). Частину для викладача доведено до ладу; нижче — те, що свідомо відкладено. Пріоритет зверху вниз.

## 1. Екрани деканату (лише перетемізовані, макети не відтворено)

- Запити на перенесення (`features/requests`): двопанельний макет, вільні слоти, діалог відхилення.
- Довідники (`features/directory`): макети груп, студентів, викладачів, аудиторій.
- Конструктор розкладу (`features/schedule-builder`): розкладка, панель конфліктів, діалог публікації.
- Майстер нового семестру (`features/semesters`): кроки 1–4 за макетами `design/artboards/WizardStep*.dc.html` (крок 4 — вибір шаблону, смуга «розставлено X з Y», список причин).
- Перегляд групи, студента, календар заходів.

## 2. Викладач: недороблене

- Заголовок журналу на мобільному переноситься на два рядки; тулбар займає багато висоти.
- Не переглянуто візуально на мобільному: екран заняття (Lesson), розклад (тиждень/день).
- Колонка «Заняття» (дата, статус) у таблиці тематичного плану: потрібна прив'язка теми до заняття в API плану тем.
- Смуга періоду атестації над датами журналу не перевірена на реальних даних (у сидах заняття не потрапляють у періоди).
- Підказка на комірці журналу й оновлена картка студента: перевірені лише на порожніх даних.
- Агрегація журналу (зведений журнал по дисципліні): журнал лишається окремим на навантаження.
- Ручне розв'язання конфліктів синхронізації (зараз LWW + сповіщення, OQ-31).
- Оцінювання (макет 4.10), історія змін оцінок, імпорт XLSX, місячний і семестровий вигляд розкладу, онбординг.

## 3. Технічне

- Запустити повний прогін з нуля після злиття (`pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm e2e`).
- Скриншоти в темній темі для переробленого журналу й дисциплін не знімалися.
- Відкриті питання продукту: `docs/OPEN_QUESTIONS.md` (OQ-23..33), рішення: `docs/DECISIONS.md` (ADR-017..022).

## 4. Після імпорту реальних даних (жовтень 2026)

- **Колонки оцінювання (практичні, модулі):** керування й введення на комп'ютері й телефоні готові (ADR-025, ADR-026); офлайн працює (ADR-027): створення й видалення самих колонок лишаються онлайн-діями.
- **Потокові лекції** (одне заняття для кількох груп): зараз лекція КІт-31…34 імпортована окремим навантаженням для кожної групи.

## 5. Безпека (відкладено на прохання власника, 7 жовтня 2026)

Перевірено: XSS-приймачів у вебі немає, сирого SQL немає, вхід валідується zod, права й ізоляція за організацією працюють, `pnpm audit --prod` чистий. Лишилося:

- Захисні заголовки (CSP, `frame-ancestors`/`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, HSTS) на API й на Cloudflare Worker.
- Глобальний ліміт частоти запитів (зараз лише вхід).
- Нейтралізація CSV-ін'єкції в експорті вичитки (комірки на `=`, `+`, `-`, `@`).
- Максимальна довжина параметра пошуку `q`; тест DOCX-відомостей на шкідливі імена.
- Змінити пароль бази Neon і пароль входу, що потрапляли в чат.
